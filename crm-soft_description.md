# EASYMED CRM Soft

Сайт EASYMED CRM Soft — это две отдельные HTML-страницы. Адрес `/login` открывает форму входа, адрес `/crm-soft` открывает рабочий экран с поиском диагноза по МКБ. Между ними нет клиентского роутера: браузер каждый раз загружает готовую страницу целиком.

Сборка кладёт страницы в папки `login/index.html` и `crm-soft/index.html`. Веб-сервер отдаёт эти файлы как индекс каталога, поэтому запрос `/login` показывает форму, а `/crm-soft` — рабочий экран. Параметры в адресе сохраняются. На форму подключаются скрипт входа и общие стили. На рабочий экран подключаются скрипт страницы, скрипт проверки сессии и те же стили. Запросы к серверу идут в каталог `php` относительно страницы: из `/login` и из `/crm-soft` это путь `../php/...`.

## Страница `/login`

Форма содержит логин, пароль и кнопку «Вход». Кнопка остаётся неактивной, пока в каждом поле меньше 6 символов. Показ пароля переключается иконкой рядом с полем.

Нажатие «Вход» прячет прошлую ошибку, показывает индикатор и отправляет GET-запрос:

`../php/login.php/login?username=...&password=...`

Суффикс `/login` в адресе скрипта — часть пути запроса. Выполняется тот же `login.php`, параметры читаются из query string.

Скрипт сверяет логин и пароль с таблицей пользователей SQNS и, если у пользователя задан IP, сравнивает его с адресом клиента. Ответ — JSON с полем `result`:

- `access` — доступ разрешён. В cookie `username` и `password` записываются на 30 дней с путём `/`. Браузер переходит на `/crm-soft`. Если вход открыли как `/login?code=КОД`, переход идёт на `/crm-soft?code=КОД`, чтобы сразу открыть этот диагноз.
- `deny` — текст «Неверный логин или пароль».
- `denyIP` — текст «IP не зарегистрирован».
- сбой сети — текст «Ошибка».

В текущем обработчике cookie и переход на `/crm-soft` назначаются сразу после любого JSON-ответа, ещё до проверки `result`. При отказе пользователь всё равно уходит на рабочую страницу; та заново проверяет cookie и возвращает его на `/login`.

## Как открывается `/crm-soft`

При загрузке сначала работает проверка сессии.

1. В адресе есть `username` и `password`, например `/crm-soft/?username=...&password=...&code=...`. Эти значения проверяются тем же `login.php` и в cookie не записываются. При `access` страница остаётся открытой. При `deny`, `denyIP` или ошибке браузер уходит на `/login`. Код диагноза, если он был в адресе, сохраняется как `/login?code=...`.
2. В адресе учётных данных нет, cookie тоже нет. Браузер сразу переходит на `/login` или `/login?code=...`.
3. Cookie есть. Они снова проверяются через `login.php`. При `deny` или ошибке сети — возврат на `/login`. При успешном ответе страница остаётся.

Рабочий скрипт повторяет ту же проверку до загрузки диагноза: без cookie и без логина с паролем в адресе он тоже отправляет на `/login`, сохраняя `code`.

Если в адресе есть `code`, страница сразу запрашивает этот диагноз, а затем убирает query string через `history.replaceState`, оставляя в строке адреса `/crm-soft`. Логин и пароль из адреса к этому моменту уже сохранены в памяти страницы, поэтому следующие запросы к API продолжают их подставлять. Если кода нет, через несколько секунд скрывается индикатор загрузки и показывается история прошлых поисков этого пользователя.

## Что делает рабочая страница

В поле «Название нозологии или код МКБ» после двух символов уходит запрос подсказок. Выбор строки, нажатие Enter или клик по истории запускают загрузку диагноза.

Дальше на экране появляются переключатели «Ребёнок / Взрослый» и «Первичный / Повторный», списки нормативных документов по диагностике и лечению и карточки:

- диагностические услуги обязательные;
- диагностические услуги по показаниям;
- немедикаментозное лечение;
- медикаментозное лечение;
- медикаментозное лечение (offlabel);
- приложение А3, таблицы.

Карточки можно сворачивать, сортировать (по алфавиту, по УУР и УДД, по критерию качества, по очередности в клинических рекомендациях) и копировать выделенные строки в буфер. Кнопка информации у строки открывает комментарий. Клик по таблице открывает её в отдельном окне. Смена возраста или документа заново собирает списки из уже загруженных данных. Очистка поиска возвращает пустой экран и историю.

Если по коду нет записи, показывается «Диагноз с таким кодом не найден». Если запись есть, но рекомендаций и стандартов нет, показывается текст, что по этому коду МКБ у Минздрава клинических рекомендаций и стандартов не предусмотрено.

История хранится в `localStorage` под ключом `mkbSearchHistory:` и логином, не больше семи последних кодов. Cookie живут 30 дней. Пока они валидны, повторное открытие `/crm-soft` не показывает форму.

## Запросы к API

Все вызовы с этих двух страниц — GET, учётные данные передаются в query string.

| Запрос | Кто вызывает | Зачем |
|---|---|---|
| `php/login.php/login?username&password` | форма входа и проверка при открытии `/crm-soft` | ответ `access`, `deny` или `denyIP`; здесь проверяется и IP |
| `php/search.php?q=` | поле поиска, от двух символов | до 100 подсказок `{ code, name }` из справочника МКБ; логин не требуется |
| `php/get-data-main.php/login?code&username&password` | загрузка выбранного диагноза | код, название, группы «ребёнок» и «взрослый», стандарты, разделённые на диагностику и лечение. Для кода `K26.0` вместо этого запроса читается локальный файл `res_K26.0_first.json` |
| `php/get-data-popup.php/login?code&username&password` | сразу после основных данных | тексты и комментарии для окна информации, ключ — `cr_db_id`; до трёх попыток |
| `php/get-data-tables.php?cr_id&username&password` | после выбора документа | таблицы приложения для текущего `cr_m_id` |

Данные диагноза, комментарии и таблицы читаются из базы SQNS после проверки логина и пароля. Подсказки поиска читаются из отдельной базы справочника МКБ. На рабочей странице также стоит счётчик Яндекс.Метрики. Форма «Напишите нам» в разметке при отправке вызывает Telegram Bot API: сначала `sendMessage`, а при вложенном изображении ещё `sendPhoto`.
